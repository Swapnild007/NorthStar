# NorthStar Curriculum Master Standard

## Purpose

NorthStar is designed as a self-directed, beginner-to-advanced learning system for **Cyber Security Management & Data Science**.

It is not an official university degree or an official IIM curriculum. The academic design is benchmarked against published university curricula, cybersecurity curricular guidance, workforce frameworks and management/analytics programmes.

## What the benchmark tells us

A complete programme cannot be only:

- cybersecurity terminology
- ethical hacking
- SOC tools
- Python
- machine learning

The published programmes consistently combine technical foundations, systems, networking, security engineering, cryptography, privacy, application security, defensive operations, forensics, risk, policy, management, analytics and applied projects.

The strongest programmes also require learners to **apply** knowledge through laboratories, projects, practicum work, cases or simulations.

## NorthStar teaching contract

Every substantive lesson should use the following sequence where appropriate:

1. **Orient** — What problem does this topic solve?
2. **Explain** — Teach the concept from first principles.
3. **Visualize** — Diagram, flow, architecture or graph.
4. **Vocabulary** — Define unfamiliar terms in plain language.
5. **Mechanism** — Explain how it actually works.
6. **Worked example** — Solve a realistic example step by step.
7. **Security interpretation** — Explain why it matters to security.
8. **Case analysis** — Make a decision from evidence.
9. **Practice** — Learner performs the task.
10. **Evidence checkpoint** — Learner records observable evidence.
11. **Common mistakes** — Correct predictable misconceptions.
12. **Notes** — Short memory aids.
13. **Q&A** — Questions with explanations, not only answers.
14. **Check** — Assessment with reasoning.
15. **Connect** — Link the lesson to later modules.

Not every topic needs every visual type. A graph belongs where quantitative reasoning benefits from it; a protocol or architecture diagram belongs where system relationships matter.

## Competency model

Lessons should progressively develop:

- knowledge
- conceptual understanding
- procedural skill
- analytical reasoning
- evidence handling
- communication
- judgement under uncertainty
- management decision-making

This follows the spirit of the NICE Task, Knowledge and Skill model rather than treating completion of a page as proof of competence.

## Current curriculum gap audit

The current 16-pathway / 140-core-lesson structure is supplemented by 7 targeted competency-completion lessons covering the remaining material gaps. The programme is designed to close genuine competency gaps rather than inflate lesson counts.

The most important missing or under-deep areas identified by the benchmark are:

1. Cryptography and key management
2. Privacy engineering and data protection
3. Digital forensics and evidence handling
4. Malware concepts and analysis foundations
5. Database security
6. Secure software and API security depth
7. Supply-chain security
8. AI/ML security and LLM security
9. Cyber law, ethics and professional responsibility
10. Business continuity, resilience and crisis management
11. Third-party and supply-chain risk
12. Mobile/IoT security
13. OT/cyber-physical security
14. Security economics and investment decisions
15. Research methodology and technical communication

The current release addresses the most important uncovered areas through targeted additions: digital forensics, malware analysis foundations, database security, API security, cyber law/ethics, mobile security, and security research/technical communication. Remaining depth should be improved through enrichment and practical evidence rather than arbitrary lesson-count inflation.

## Assessment architecture

NorthStar should eventually assess four levels:

### Level 1 — Recall
Definitions, vocabulary and basic recognition.

### Level 2 — Understanding
Explain a mechanism in the learner's own words.

### Level 3 — Application
Perform a controlled technical or analytical task.

### Level 4 — Professional judgement
Interpret evidence, identify uncertainty, select controls, communicate trade-offs and defend a decision.

## Practical learning

Labs should progress from:

**guided → semi-guided → investigation → design → enterprise simulation**

The system must never pretend that a fake button click is a real security lab. Where execution infrastructure is unavailable, NorthStar should clearly label the activity as a simulation or evidence exercise.

## Quality gate

A lesson is not considered complete merely because it has a title, paragraph and quiz.

A mature lesson should answer:

> Can a true beginner understand it, explain it, apply it, produce evidence, recognize mistakes, and connect it to the next competency?

If not, the lesson needs more authoring.
